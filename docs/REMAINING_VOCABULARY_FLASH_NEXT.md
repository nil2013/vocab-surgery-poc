## 追加削減の候補

「現 policy で書けるか」の基準：`explicitForbidden` には任意の code point を指定でき、その字を含む非保護 token は全体が削除される。ただし `protectMath=true` の下では Math 属性の文字は指定できない。token 単位で削除を指定する機能は、現在の `CharacterPolicy` にない（`PruningPolicy` を実装すれば書ける）。どの候補を削除しても基礎 bytes は残るので、その文字の入出力は可能なまま残り、生成を禁止できる保証はない。

- **文字単位では拾えない**：辞書外の語のうち 9,875 行は構成漢字がすべて常用漢字で、文字単位の規則では大半を拾えない。
- **誤検出（判断）**：辞書外から無作為に 40 件を読むと、日本語として自然なのは `作品展` と `精神上` の 2 件、境界例は `隔音` と `旋即` の 2 件だった。分解できる 818 行には `第十六条 第十一章 公示催告 工程管理` のように日本語でも成立する語が多い（無作為 40 件中 8〜10 件）。逆に、辞書にある側にも `呼和 社保 牛股 依托 吉林 湖南省` などが残る。
- **cleanup で追加される行**：`有期徒刑 国家和地区 越来越多 等方面的`、`股份有限公司 或以其他方式`。
- **簡体字形の上位**：`于` 152、`气` 118、`么` 97、`种` 88、`并` 79、`从` 76、`价` 64、`几` 58、`确` 53、`阳` 51 行。どれも JIS（一部は漢検にも）由来なので参照集合に入っている。v2 で禁止した 5 字と同じ性質の字である。
- **繁体字・旧字体形の例**：`會 發 對 體 學 點 當 經 們 沒 關 麼`。基準を常用漢字だけにすると 1,724 行に増え、`這 來 國 實` のように人名用の異体字も加わる。

### 部分 UTF-8（設計上の保護）

944 行は単独では完全な文字にならない byte 列で、`PartialUtf8` として保護されている。末尾の不完全な列を補完しうる文字の Script で分けると、Han 330 行、Hangul 259 行（＋7 行）、その他は Indic・Ethiopic・Cyrillic・Arabic が少数。

補完すると必ず禁止 Script の文字になるものが **270 行**ある（`d0 d1` は Cyrillic、`eb ec ec9d` は Hangul、`e0a4` は Devanagari）。そのうち 10 行は、残っている別の merge の部品になっている。

削除するには `PartialUtf8` 保護を緩める新しい機能が要る。基礎 bytes が残るので表現力は落ちず、Hangul・Cyrillic を生成するときの近道がなくなるだけで、生成を禁止できる保証にはならない（判断）。

## Policy と衝突する保護 token

なし。残存行で禁止理由を持つもの、regex による再判定で違反になるものは、どちらも 0 行。Math だけからなる 128 行に禁止 Script の文字はなく、Coder-Next で問題になった `؈` を含む残存 token も 0 行。added tokens 33 行も禁止文字を含まない。

部分 UTF-8 の 270 行は、policy の文言上は衝突しない（判定対象の文字を含まない）。ただし言語混入を防ぐという目的から見ると、意図とずれた残存である（判断）。

## 判断事項と限界

ユーザーが決めること：

- (a) 文字単位で書ける群 A を採るか。
- (b) token 単位で削除を指定する機能を実装するか。辞書外の Han 語彙、ASCII の外国語、Greek の語片、128 の倍数に合わせる最終調整のいずれにも必要になる。
- (c) 部分 UTF-8 の 270 行の保護を緩めるか。
- (d) Greek を残す方針を Flash-Next でも維持するか。

限界：

- 辞書や word list による判定は heuristic で、誤検出率は少数の抜き取りを読んだうえでの判断である。
- 件数は語彙の行数で、使用頻度ではない。混入や出力エントロピーへの効果は推論による評価でしか分からない。
- cleanup の再現は Python 実装による。
